# Tech Stack — AI Career Companion Agent

## Backend
- **Language:** Python 3.11+
- **Framework:** FastAPI (async, auto-generated OpenAPI docs at `/docs`)
- **Server:** Uvicorn
- **Validation/Serialization:** Pydantic v2

## Database
- **Engine:** PostgreSQL
- **ORM:** SQLAlchemy 2.x
- **Driver:** psycopg2-binary

## Authentication (App Layer)
- **Password hashing:** `passlib[bcrypt]` (bcrypt pinned to `4.0.1` for compatibility)
- **Session tokens:** JWT (`python-jose`), bearer tokens with a 7-day expiry by default
- **Flow:** register/login issue a token; every profile/resume/match/application endpoint requires it and is scoped to the logged-in student only (`require_self` dependency, 403 on mismatch)

## AI / LLM
- **Provider:** GroqCloud (`openai` Python SDK with `GROQ_BASE_URL`) or OpenAI
  as a fallback
- **Use in Milestone 1:** structured extraction of skills, education,
  experience, and projects from unstructured resume text (JSON-schema
  constrained prompting)
- **Use in Milestone 2:** compatibility scoring + reasoning for the
  Job-Resume Matching Agent (one call per shortlisted job, JSON-schema
  constrained prompting)
- **Use in Milestone 3:** categorized skill-gap analysis, tailored resume +
  cover letter generation (with an explicit no-fabrication constraint),
  job-specific interview prep (5 question categories + guidance + revision
  topics, reusing a saved skill-gap analysis when available), and the
  free-form Career Assistant chat (no JSON mode — conversational replies
  grounded in a per-turn context block built from the student's profile,
  matches, and any saved agent outputs for the job being discussed)

## RAG / Semantic Search (Milestone 2)
- **Embedding model:** `sentence-transformers` (`all-MiniLM-L6-v2`) — runs
  locally after a one-time model download, no paid API or key required
- **Vector store:** ChromaDB, embedded/local (no separate server process),
  persisted to `backend/vector_store/`
- **Dataset:** 180 synthetic-but-realistic internship postings across 19
  domains, generated by `database/generate_job_postings.py` (see
  `docs/job_posting_schema.md`)
- **Chunking strategy:** each posting split into up to 3 semantic chunks
  (overview, responsibilities, requirements) — see `docs/architecture.md` §3

## Resume Processing
- **PDF text extraction:** `pdfplumber`
- **DOCX text extraction:** `python-docx`

## Frontend
- **HTML5 / CSS3 / vanilla JavaScript**
- No frontend framework/build step — runs by opening the file directly or
  via a static server, keeping local VS Code setup friction-free

## Config & Environment
- `python-dotenv` for environment variables (`.env`)
- CORS enabled on the FastAPI app so the static frontend can call the API
  from a different local port

## Dev Environment
- **Editor:** VS Code
- **Version control:** Git + GitHub

## AI Chat Bot / Mock Interview
- **Two modes:** general domain practice (25 questions from the curated bank below) or job-specific practice — pick any matched/applied internship and the set is generated from that job's Interview Prep Plan (M3.3: technical, resume-based, project-based, role-specific, and HR questions grounded in the real posting and the student's actual skill gaps), auto-generating that plan first if it doesn't exist yet
- **Question bank (general mode):** 563 curated questions across 19 domains (technical + behavioral), generated by `database/generate_interview_questions.py` — see `docs/interview_question_bank.md` for sourcing rationale
- **Voice input/output:** Web Speech API (`SpeechRecognition` for voice-to-text answers, `SpeechSynthesis` to read questions aloud) — native browser feature, no external speech API or cost; falls back to typed answers in unsupported browsers
- **Feedback generation:** OpenAI-compatible LLM call over the full Q&A transcript (and the job's details, for job-specific sets) — overall score, strengths, and a structured improvement list where each item names the gap, explains *why* it matters for that role, and names real, well-known resources (docs, free courses, practice platforms) to work on it, plus a personalized recommendations paragraph

## Application Toolkit & Career Assistant (Milestone 3)
- **Skill Gap, Resume/Cover Letter, and Interview Prep agents:** each is one Postgres row per `(student, job)` pair, overwritten on re-generation, editable by the student where it makes sense (tailored resume/cover letter)
- **Frontend:** a single "Application Toolkit" dashboard with sub-tabs (Skill Gap / Tailored Resume / Cover Letter / Interview Prep) sharing one job picker, so all four stay grounded in the same selected posting
- **Career Assistant:** persistent per-student chat log (Postgres), free-form (non-JSON-mode) LLM replies, bounded conversation history (last 20 messages) plus a context block assembled fresh per turn — reuses `matching_agent.py`'s profile/job summary builders and, for general questions with no job selected, falls back to a live RAG semantic search over the knowledge base

## Planned for future milestones (not yet implemented)
- Multi-agent orchestration beyond the Career Assistant's direct context-assembly (e.g. explicit tool-calling between agents)
- Richer application statuses (shortlisted/interviewing/rejected/offer)
